Portfolio الجيد لا يحتاج عشرات المشاريع. ثلاثة أو أربعة مشاريع مكتملة وموثقة قد تقول عنك أكثر من عشرين مستودعًا منسوخًا من دورات.

## 1. مدير مهام بميزات حقيقية

أضف فلاتر، مواعيد، بحثًا، تخزينًا دائمًا واختبارات. لا تتوقف عند إضافة وحذف مهمة.

## 2. لوحة مصروفات شخصية

تعامل مع تصنيفات وتواريخ ورسوم وميزانية شهرية واستيراد وتصدير البيانات.

## 3. تطبيق ملاحظات مع بحث

أضف Markdown ووسومًا وبحثًا سريعًا وحفظًا محليًا أو سحابيًا.

## 4. Dashboard لبيانات عامة

استخدم API موثوقة، تعامل مع التحميل والأخطاء والتخزين المؤقت واعرض البيانات بوضوح.

## 5. نظام حجوزات مصغر

ابنِ قواعد تمنع تضارب المواعيد، مع صلاحيات مختلفة للمستخدم والمدير.

## 6. أداة للمطورين

مثل JSON formatter أو مقارنة نصوص أو مولد README. الأدوات الصغيرة المفيدة ممتازة لإظهار اهتمامك بتجربة المستخدم.

## 7. تطبيق يستخدم AI بحدود واضحة

بدل «Chatbot آخر»، حل مشكلة محددة: تلخيص مستند، تصنيف محتوى أو اقتراح تحسينات، مع إظهار الأخطاء والتحقق من المخرجات.

## 8. API موثقة

ابنِ API مع مصادقة، validation، pagination، rate limiting واختبارات.

## 9. مشروع Open Source صغير

انشر أداة قابلة للتثبيت أو مكتبة صغيرة مع Issues وChangelog وتوثيق جيد.

## 10. مشروع يحل مشكلة لديك فعلًا

هذا غالبًا أفضل مشروع؛ لأنك تعرف المستخدم والمشكلة وستواجه قرارات حقيقية لا توجد في Tutorial.

## ماذا تكتب في README؟

اشرح المشكلة، الحل، التقنيات، طريقة التشغيل، القرارات المهمة، لقطات الشاشة، القيود وما الذي ستطوره لاحقًا.

## لا تضع أسرارًا في المستودع

استخدم Environment Variables ولا ترفع tokens أو كلمات المرور أو مفاتيح الخدمة. راجع الملفات قبل جعل المشروع عامًا.

## الخلاصة

المشروع القوي يوضح أنك تستطيع الانتقال من فكرة إلى منتج يعمل، وأنك تفهم ما بنيته. إذا لم تحدد تخصصك بعد، ابدأ من [دليل اختيار المسار](/blog/choose-programming-path-2026/).
